AINE · public core · Apache-2.0 / MIT

Evidence for what an AI agent did to your repos, and a boundary it cannot write past.

Three small tools. One scans a multi-repo workspace into a portable snapshot with drift findings, read-only. One runs a coding agent inside a declared file scope the OS enforces, and freezes a report of what it did. One turns snapshots and reports into approval, change-request and remediation records you can audit.

Built by one person and used on the author's own seven repositories. No hosted service, no SaaS, no telemetry. If you try it and it does nothing for you, say so; that is the most useful reply.

Three doors
aine-registry

Scans one or more workspace roots. Emits projects, ownership, dependencies and relationships as one JSON snapshot, plus findings where declared truth and the tree disagree.

Python · stdlib only · v1.7.0 · Apache-2.0 github.com/williamlabdev/aine-registry
orvena

Runs a coding agent inside a file scope you declare. The OS refuses out-of-scope writes, so the boundary does not depend on the prompt. Wraps the Codex CLI today; every run leaves a frozen evidence report.

Rust · single binary · v0.9.0 · MIT github.com/williamlabdev/Orvena
aine-control-plane

Contracts and a reference server for approval, change-request and remediation records over the snapshot and the agent's evidence. Read-only proposals; every decision is an explicit record. Ships with a local React UI.

Python · zero dependencies · v0.8.0 · Apache-2.0 github.com/williamlabdev/aine-control-plane
Is this for you

Probably yes

  • You run a developer portal (Backstage, Port, Cortex, OpsLevel) and the catalog drifts from the repos.
  • A small team ships with coding agents and review has become "re-read the whole diff".
  • You want to know what an agent touched before you trust its PR.

Probably not

  • You want an agent that writes code. These tools never write to your repos.
  • You need a hosted dashboard with SSO. There is none.
  • One repo, one developer, no agents. There is nothing here to govern yet.
Five minutes
01

Snapshot a workspace you already have

git clone https://github.com/williamlabdev/aine-registry
cd aine-registry
python3 registry/aine_registry.py --root /path/to/your/workspace discover --output snapshot.json
python3 registry/aine_registry.py --snapshot snapshot.json findings
python3 registry/aine_registry.py --snapshot snapshot.json view > portfolio.html

Nothing is written inside your workspace. Local config never travels with the snapshot, and the HTML view is a static file you can hand to someone.

measured 2026-09-08 on the author's workspace: 7 projects, 257 findings, 36 s, 3.4 MB snapshot

02

Run an agent inside a declared scope

cargo install --git https://github.com/williamlabdev/Orvena orvena-cli
orvena init --provider <provider> --model <model>
orvena run --agent codex "summarize the repository"

Declare which files a task may modify; everything else is read-only. The report lands in .orvena/runs/<timestamp>/evidence.json and records what the run did, not what it was told. The boundary is the filesystem: the agent still reaches its model provider over the network.

03

Turn evidence into records

git clone https://github.com/williamlabdev/aine-control-plane
cd aine-control-plane
PYTHONPATH=. python3 examples/run_server.py --db ./control-plane.sqlite
# second terminal: seed a snapshot, then open the UI
curl -X POST http://127.0.0.1:8787/v1/snapshots -H 'content-type: application/json' --data @snapshot.json
cd ui && npm ci --include=optional --ignore-scripts && npm run dev

A loopback server plus a local UI showing projects, relationships, impact, evidence and the change-request and remediation workflows. Needs Node for the UI. Optional; steps 01 and 02 stand on their own.

What this is not

Not a hosted product. Not an agent. Not a Backstage plugin, yet: a catalog-info.yaml import/export is the first thing that gets built if a portal team asks for it. Not proven at scale: the largest workspace it has run on is the author's own. Not a network sandbox: Orvena bounds files, not traffic.
