aine-control-plane · public core · v0.8.0 · Apache-2.0

Read-only governance records over a portfolio snapshot and the evidence agents leave behind.

A dependency-free Python package. It ingests a portable aine-registry snapshot, evaluates policy and authorization deterministically, and keeps approval, change-request, remediation-plan and runner-session records where every decision is an explicit, append-only entry. A reference HTTP server and a local React UI sit on the same read-only boundary.

This repository is the public core boundary. It is not a hosted control plane, not an agent runner, and not a provider integration product. Built by one person and used on the author's own repositories.

What it holds
  • Portable Registry snapshot ingest, with project, artifact, dependency, relationship and source-of-truth views, plus impact analysis.
  • Policy evaluation, advisory by default or opt-in enforced, with explicit unknown and conflict states.
  • Deterministic RBAC/ABAC authorization and retention evaluation that never deletes.
  • Approval, change-request, remediation-plan and runner-session workflows as read-only proposals; every decision is a record.
  • Append-only SQLite evidence and audit storage; JSONL, SQLite and static-fixture reference adapters.
  • integration-observation.v1 records that link a producer run to an ingested snapshot, for report-only Orvena and airt evidence.
  • JSON Schemas, fixtures and conformance tests for everything under the aine.control-plane.*.v1 wire namespace.
Six contracts

Everything a deployment plugs in is one of these typing.Protocol classes in aine_control_plane/contracts.py. Implement the ones you need; the core never imports a provider SDK.

CredentialProvider

Resolves a runtime credential reference without exposing its value.

IdentityAdapter

Resolves an external subject into portable policy attributes.

EvidenceSourceAdapter

Collects portable evidence from an external read-only source, such as CI results or an agent run report.

EvidenceSinkAdapter

Persists or forwards portable records without changing their meaning.

PortfolioViewAdapter

Renders or publishes a portable portfolio snapshot.

RetentionAdapter

Evaluates retention without deleting or silently mutating records.

Five minutes
01

Evaluate one policy in plain Python

git clone https://github.com/williamlabdev/aine-control-plane
cd aine-control-plane
PYTHONPATH=. python3 - <<'EOF'
from aine_control_plane.contracts import AdapterContext
from aine_control_plane.governance import evaluate_policy

context = AdapterContext("request-1", actor={"id": "developer"})
decision = evaluate_policy(
    {"policy_id": "release", "required_checks": ["tests"]},
    [{"check_id": "tests", "status": "pass"}],
    context,
)
print(decision["status"])
EOF

Python 3.9 or newer, nothing to install. Prints pass.

02

Run the reference server and seed a snapshot

PYTHONPATH=. python3 examples/run_server.py --db ./control-plane.sqlite
# second terminal
curl -X POST http://127.0.0.1:8787/v1/snapshots \
  -H 'X-AINE-Actor: developer' -H 'content-type: application/json' \
  --data @aine_control_plane/fixtures/registry_snapshot.json

Loopback only, no auth beyond the actor header, SQLite on disk. Replace the fixture with a snapshot from aine-registry discover to see your own portfolio.

03

Open the local UI

cd ui && npm ci --include=optional --ignore-scripts && npm run dev

Projects, relationships, source-of-truth rules, impact, evidence, audit events, and the change-request, remediation and runner workflows. Vite proxies /v1 to the server. Needs Node; optional.

Where it sits

Upstream

  • aine-registry produces the portable snapshot this package ingests. The snapshot schema is vendored here and checked byte-for-byte in the test suite.

Evidence producers

  • Orvena runs a coding agent inside an OS-enforced file scope and freezes a run report. That report enters here as a report-only observation, never as a command.
What this is not

Not hosted. Not an agent, and it never writes to a repository. Not a Backstage plugin, yet: a catalog-info.yaml adapter is the first thing that gets built if a portal team asks for it. Not proven beyond the author's own portfolio.
